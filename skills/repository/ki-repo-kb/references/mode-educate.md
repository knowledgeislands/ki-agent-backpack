# Mode EDUCATE — scaffold a new base's structure

_On-demand procedure for kb's EDUCATE mode. The shared model — the five-zone structure, routing test, memory cascade, project bindings, and Step 1 (Load context) — lives in [`SKILL.md`](../SKILL.md) and is already loaded; this file is the procedure only._

1. Create the zone skeleton — Calendar / Pillars / Resources / Streams, plus the inbound `+` and outbound `-` zones — and the root `Admin/MEMORY.md`.
2. Create the two `Admin/` subdivisions with stub index notes and governance documents:
   - `Admin/Governance/Governance.md` — title, purpose, link to decisions folder.
   - `Admin/Governance/Charter.md` — stub with headings: Purpose, Scope, Owner, Established.
   - `Admin/Governance/Conformance.md` — stub table: Skill | Adoption date | Notes.
   - `Admin/Operations/Operations.md` — title, purpose, link to activities index.
3. Copy the zone-scoped templates from `assets/templates/` into a `Templates/` staging folder in the base (or a configured location), so the base owner has starter stubs for common note types. Do not create this folder if the base already has templates in place.
4. Seed each zone's note conventions (frontmatter, naming) from the structure model.
5. Create `Streams/Roadmap/` for `ki-work-roadmap`, and `Admin/Operations/Activities/Activities.md` when the base adopts its first Activity, per [the Streams structure](standard-streams-structure.md) and [Activity](standard-activities.md) standards.
6. In a territory's Capital, add the [principal](standard-principal.md) entry points, `Admin/Governance/Known Lands.md`, `Admin/Governance/Conventions/Conventions.md` and `Admin/Operations/Processes/Enactment Process.md`, and the exact `+/_ACQUIRED/README.md`; anchor [the Enactment gate](standard-enactment-process.md#42-canonical-change-gate) in the root `AGENTS.md`. Review and author their local content before declaring the base operational.
7. Hand ongoing capture to the SAVE / EXTRACT / DIGEST modes.
